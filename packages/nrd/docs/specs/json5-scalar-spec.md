# JSON5-объект как скаляр атрибута — дополнение к format-spec §3

Статус: спека-дополнение по. Решения 1–6 приняты в диалоге 16.07 (зафиксированы в таске), п.7 уточнён и подтверждён owner 16.07 (см. §2). Spec ready — реализовано.

## 1. Правило

`$attr: {json5}` — значение атрибута может быть однострочным JSON5-объектом.

- **Детекция по форме, строгая:** значение (после трима) начинается с `{` И заканчивается `}` → обязано быть валидным однострочным JSON5-объектом. Битое → **ошибка парса с номером строки**, не молчаливый откат в строку (молчаливый откат = новый класс coerce-багов: опечатка всплывает через три слоя рантайма undefined-ом).
- Значение с `{` в начале, но без `}` в конце (`{name} says hi`) → обычная строка, конфликта с прозой нет.
- Строка, целиком обёрнутая в фигурные, — через эскейп начала: `$k: \{literal}` → строка `{literal}` (прецедент — эскейп имени в nr-chat).
- Только объект `{...}`. Массивы НЕ вводятся: список — существующий flow-литерал `$[...]` (§4). Вложенные структуры внутри JSON5-объекта — легитимны (это JSON5, не flow).

## 2. Место в пайплайне (п.7 финализирован 16.07)

**Исходная формулировка п.7 была противоречива** и в этой редакции снята. Она гласила: «JSON5-коэрция живёт в той же точке, что обычная коэрсия скаляра, то есть применяется к значению после резолва плейсхолдеров». В ядре это **две разные точки**, а не одна:

- обычная коэрсия — **parse-time** (`parseAttributeValue`); значение с `${}` до неё не доходит вовсе, оно становится InterpolatedValue;
- **после резолва коэрсии нет ни одной**: `resolve()` и `resolveBlockValue()` возвращают `string` по контракту.

«Та же точка» дала бы parse-time — и тогда шаблонизированные объекты (мотивация п.7) невозможны. «После резолва» — новая точка, которой не существовало.

**Решение (owner, 16.07): две точки, JSON5-only.** Коэрсия — свойство **позиции значения атрибута**, а не момента пайплайна; в этой позиции она применяется дважды:

1. **parse-time** — значение без `${}`, прошедшее детекцию, парсится в объект сразу;
2. **post-resolve** — значение с `${}` остаётся InterpolatedValue (§7.2 контракт InterpolatedValue не меняется), а после резолва результат проходит **только JSON5-детекцию**.

**Точки взаимоисключающие: значение проходит ровно одну.** Точка 2 применяется **только к тому, что пропустило точку 1** (то есть к InterpolatedValue). Значение, уже коэрснутое парсером, имеет финальный тип, и повторная детекция запрещена — это двойная коэрсия.

Правило не косметическое, а несущее: эскейп и кавычки **потребляются в точке 1**, и к точке 2 строка снова выглядит формой. Без этого правила

```
$lit: \{not json}   → точка 1: строка `{not json}` → точка 2 снова видит форму → ОШИБКА
$k: "{a: 1}"        → точка 1: строка `{a: 1}`     → точка 2 снова видит форму → молча ОБЪЕКТ
```

— то есть `\{` и кавычки переставали бы работать ровно там, где они и нужны. (Поймано e2e-прогоном 16.07: юнит-тест на `\{` проверял только выход парсера и дефект не видел.)

### 2.1 Eligibility — по сырой форме, до резолва

**Право на пост-резолвную детекцию определяется raw ДО резолва, а не результатом после.** Значение eligible ⇔ оно пропустило точку 1 (InterpolatedValue) **И** его `raw` после трима сам начинается `{` и кончается `}`.

- Eligible-значение после резолва идёт в `parseJson5` **безусловно**: форма raw гарантирует форму результата (ведущая `{` и хвостовая `}` — литералы, плейсхолдеры строго внутри), поэтому проверять форму повторно нечего. Битое → **ошибка**.
- **Не-object-shaped raw не детектится НИКОГДА**, чем бы резолв ни обернулся:

```
$x: "{a: 1}"
$n: ${x}     → raw `${x}` — не форма → строка `{a: 1}`, НЕ объект
```

Это та же принятая асимметрия, доведённая до конца: **подстановка не меняет тип**. Иначе тип значения зависел бы от содержимого переменной — `${x}` был бы то строкой, то объектом, и автор документа не мог бы прочитать тип по своему же тексту. Право на тип даёт форма, которую автор написал, а не то, что пришло из рантайма.

(Дефект, который это закрывает, был живым: до финализации `$n: ${x}` при `x = "{a: 1}"` возвращал объект.)

Следствие, ради которого выбрана вторая точка: **шаблонизированные объекты легитимны** — `$json: {model: '${model}', retries: 2}` после резолва становится объектом. Пример format-spec §3 сохраняет свою механику (кавычки принадлежат JSON, `${}` резолвится), меняется только тип результата: был текст, похожий на JSON, — стал объект.

**Асимметрия — намеренная и зафиксирована.** Post-resolve точка коэрсирует **только JSON5**, не скаляры:

```
$json: {a: ${x}}   (x = "42")  → объект {a: 42}   — JSON5-детекция после резолва
$n: ${x}           (x = "42")  → строка "42"      — коэрсии скаляров после резолва НЕТ
```

Пост-резолвная коэрсия скаляров сюда **не вводится**: это и правка §7.2/§9 для всех потребителей интерполяции сразу — за рамками.

**Цена, принятая вместе с решением:** `resolveBlockValue()` расширяет тип возврата `string` → `string | Json5Object` (правка format-spec §7.2/§9); conformance `self-extends` §C3 переписывается под новый тип. `resolve()` остаётся `string → string` — это текстовый уровень, `quote-semantics` B2 (живой инцидент 07.07) не затронут.

Миграционное следствие: существующие документы, где значение вида `{...}` использовалось как сырая строка, меняют тип значения; намеренная строка получает `\{`. **Аудит корпусов выполнен (16.07): 0 совпадений** на 91 mdd/mdz-документе (`S:\nrlib`, `S:\skills`, `S:\appz`) и 0 в легаси `S:\libs`. Реального миграционного долга нет.

Схема (Спека 3) остаётся главнее коэрсии: поле типа `string` → значение остаётся строкой, детекция не применяется.

**Границы позиции.** Детекция живёт **только в позиции значения атрибута** — не в `coerce()`. Следствия, сохраняющие FINAL-грамматику как есть:

- **элементы flow-литерала** (§4 «только скаляры; вложенные объекты не поддерживаются») — детекция не применяется: `$[{a: 1}]` остаётся списком строк;
- **ячейки tbl** (§5) — не применяется; структура в таблице — типизированный заголовок (§5.4).

## 3. Каскад

Атомарность: JSON5-значение при last-wins заменяется **целиком**, deep-merge запрещён. Нужна гранулярная каскадируемость полей → блочная вложенность, как всегда. Каскад остаётся тупым.

## 4. Доступ внутрь

`${attr.path}` в глубину JSON5-значения — **фаза 1.1**, отдельная от ввода фичи. В v1 значение доступно только целиком (`${attr}` → объект). Путь внутрь даёт `undefined` в lenient и ошибку в strict — обычное поведение `walk` для значения без `cast` (объект не обёрнут в IContext); отдельный запрет не нужен.

**Целиком — через контекст, не через текст.** Объект доступен целиком тому, кто читает значение атрибута (`self.get(['json'])` → объект). `${}` — текстовая интерполяция, и алиас объекта даёт **текст**, а не объект:

```
$json: {model: 'gpt'}
$copy: ${json}        → текст `{model: 'gpt'}` (raw `${json}` не форма → §2.1)
```

`${attr}` на объекте разворачивается через `valueToText` в канонический relaxed JSON5 (§5) — это делает ссылку осмысленной (объект попадает в промпт/тело как канонический текст) вместо литерала `${json}`. Ветка строго аддитивна: раньше объект в `valueToText` не имел ветки вовсе и давал `undefined` (lenient — литерал `${json}`, strict — ошибка), то есть ни один работавший кейс не меняет поведения.

Алиасa «объект → объект» в v1 нет и он не нужен: гранулярность и переиспользование структуры — блочная вложенность (§8 канона), а не текстовые ссылки.

## 5. Сериализация

Эмит — канонический relaxed JSON5 одной строкой (правила — спека nr-chat §3: голые ключи по `/^[A-Za-z_$][\w$]*$/`, одинарные кавычки, литералы, один пробел после `:` и `,`). Аналога rawMeta нет: сериализатор nrd эмитит канонично; байт-точность документов — забота хирургических инструментов, не сериализатора.

**Строка-в-фигурных на эмите — эскейп, не кавычки.** Строковый скаляр, который целиком выглядит как `{...}`, эмитится с ведущим `\{`, иначе он перечитался бы объектом (round-trip). Это тот же идиом, что уже действует для ведущего `sigil[` → `\[` (serialize-spec §1.5): ведущий триггер конструкции гасится эскейпом. Кавычки тоже дают корректный round-trip (`isFullyQuoted` проверяется раньше детекции и форсирует строку), но канон эмита — эскейп.

Round-trip канонического объекта байт-точен: `{model: 'gpt', retries: 2}` → parse → stringify → тот же текст.

## 6. Реализация

- Парсер — **рантайм-зависимость `@kerneldreams/nrd/chat`** (`parseJson5`/`stringifyJson5`). НЕ npm `json5`, НЕ вендор: nrd-core — стек, не zero-dep лист (DECISIONS nr-system, 2026-07-16 «Иерархия зависимостей»). Выделение общего nr-json5 — только при появлении второго zero-dep потребителя, на импорт nrd-core не влияет (nr-chat реэкспортирует).
- Текущая коэрция скаляров не меняется (её баги —, независимо). Правило — добавка поверх.
- Портируемость ядра (§3 format-spec: коэрсия одинакова на всех языках): JSON5-грамматика заморожена (2018), референс кросс-языковой конформности — тот же официальный сьют, что в nr-chat.

**Порядок в `parseAttributeValue` (важен, иначе эскейп течёт):**

1. flow-литерал (`sigil[`) — без изменений;
2. `isFullyQuoted` → `coerce` — кавычки форсируют строку раньше детекции (§3 канона);
3. `${}` / opt-out → InterpolatedValue — детекция откладывается до post-resolve;
4. **детекция brace-shape — на СЫРОМ значении, до `unescape`.** Иначе `\{literal}` сначала развернулось бы в `{literal}` и тут же было поймано детекцией. Сырое значение начинается с `\` → не brace-shape → дальше обычный путь;
5. `coerce(unescape(...))` — без изменений.

**Известная коллизия (документируется, не лечится):** объект с полями ровно `raw` и `placeholders` (`$k: {raw: 'x', placeholders: []}`) неотличим от InterpolatedValue для duck-типизированного `isInterpolated`. Патология того же класса, что коллизия `1.10` в §3 канона; лечится кавычками/эскейпом.

**Ошибка парса:** `Json5ParseError` (`name: 'Json5ParseError'`) с номером строки документа и ключом атрибута, поверх позиции от JSON5-парсера. Конвенция — как `TableParseError` (§5).
