# Спека — Document ⇄ JSON (`toJson` / `fromJson`)

**Статус:** v1, реализовано в `@kerneldreams/nrd` 1.2.0, `src/core/json.ts`.
**Ступень:** корень `nrd` (ноль environment API, работает в GAS); реэкспорт — `nrd/format`.
**Первый потребитель:** стартовый state бота одной строкой внутри гритинга.

---

## 1. Зачем и чем это НЕ является

`serialize`/`parse` — текст формата для людей. Здесь — машинная форма того же
`Document`: одна строка без переводов строк, пишется `JSON.stringify(toJson(doc))`,
читается `fromJson(JSON.parse(s))` (или `fromJson(s)`). Обычный JSON, не JSON5.

Это НЕ schema-слой (serialize-spec §3): никакого отображения на «удобный объект»
по схеме. Форма — дерево `Document` один в один, чтобы обход был без потерь
для любого документа, без знания его смысла.

## 2. API

```ts
function toJson(doc: Document | NRDocument): unknown  // JSON-совместимое значение
function fromJson(value: unknown): Document     // значение или его JSON-строка
const JSON_FORM_VERSION = 1
```

`NRDocument` (выход `parseDocument`) — берётся его `.doc` (по форме, не `instanceof`: две
копии пакета в дереве не ломают); прочее — `TypeError` с типом аргумента (1.5.1).

Контракт: `fromJson(JSON.parse(JSON.stringify(toJson(doc)))) ≡ doc` (глубокое равенство;
`pos` не переносится — его никто не заполняет).

## 3. Форма

```
Doc   = { "v": 1, "sigil": "@" | "$", "root": Block }
Block = { "name": string, "id"?: string, "level": int,
          "attrs"?: [Attr...], "body"?: Text, "children"?: [Block...] }
Attr  = [ key: [string...], value: Value ]
Value = null | boolean | number | string        — скаляр как его дала коэрсия
      | [ Item... ]                             — список @[...]
      | { "$i": string, "p": [[start, end]...] } — значение с ${...}
      | { "$o": { ...plain JSON... } }          — JSON5-объект
Item  = null | boolean | number | string | { "$i": ..., "p": ... }
Text  = string | { "$i": ..., "p": ... }        — тело блока
```

- Пустые `attrs`/`children` и отсутствующие `id`/`body` не пишутся.
- `key` — сегменты точечного ключа (`@geo.city` → `["geo","city"]`); порядок атрибутов
  сохраняется (важен для last-wins и коллекций повторов).
- `$i`: `raw` как в `InterpolatedValue` (эскейпы не развёрнуты), `p` — спаны `${…}`
  смещениями в `raw`; текст выражения восстанавливается из спана.
- Числа — как их дала коэрсия (`72.5`, `-0.25`, `3`). `-0` выходит `0` (свойство JSON).

## 4. Устойчивость к росту

- Форма расширяется **только добавлением полей**. Читатель игнорирует неизвестные поля
  на любом уровне (документ, блок, `$i`-объект) и лишние элементы пары `Attr`.
- `v` пишется, но `fromJson` его не проверяет: несовместимая смена формы (если
  случится) поднимет `v`, и тогда проверка появится.
- Опущенные поля — дефолты: `sigil` → `"@"`, `root` → пустой корень, `name` → `""`,
  `level` → уровень родителя + 1 (корень 0), `key` строкой → один сегмент, `p` → `[]`.
- Нарушение формы у известного поля (не тот тип, объект-значение без тега `$i`/`$o`,
  битый спан) — `TypeError` с путём до места.

## 5. Границы

- `toJson` бросает `TypeError` на числе, не представимом в JSON (`NaN`, `±Infinity`
  внутри JSON5-объекта), — молчаливый `null` был бы потерей.
- `InterpolatedValue` распознаётся по форме `{raw: string, placeholders: []}`;
  JSON5-объект ровно с такими ключами неотличим в AST и уйдёт как `$i` — артефакт
  AST nr-md, не этой формы.
