# Граница формат/движок внутри nrd-core — спека

Статус: spec ready. Linear:.
Место кода: `S:\nrlib\nrd-core`. Наружу пакет не меняется — все текущие импорты потребителей работают как раньше.

## 1. Назначение

nrd-core сегодня — два пакета под одним именем: **кодек** mdd/mdz (текст ↔ структура) и **движок** контекста (протокол IContext + резолв `${}`). Спека фиксирует границу между ними внутри пакета, не вынося кодек наружу.

Цель шага: (а) остановить дальнейшее срастание — новые фичи ложатся по свою сторону границы; (б) сделать будущий вынос кодека в отдельный zero-dep пакет переносом папки, а не проектом. Сам вынос — НЕ в этой таске; триггер выноса — потребитель кодека вне стека (браузер, порт, tavern-сторона), см. DECISIONS nr-system 16.07 (json5-триггер сработает тем же событием).

## 2. Разбиение модулей

**format/** (кодек, движка не знает):
`types` (без Value — см. §3.1) · `coerce` · `value` · `placeholder` · `json5-value` · `parser` · `serialize` · `typed-header` · `schema` · `includes`.

**движок** (остаётся в корне src/, кодек импортировать МОЖНО — направление вниз легально):
`icontext` · `contexts` · `walk` · `resolve` · `functions` · `cartesian` · `document`.

Решения по спорным модулям (закрыты, не пересматривать):
- **splitter** — модуля больше нет (4.0.0): `%role`-ленту разбирает `@kerneldreams/nrd/chat`, каст `messages` зовёт его из `document`. Решение «сплиттер — движок» осталось верным по сути: разбор ленты не движок формата.
- **document (NRDocument)** — движок. Это биндинг кодека к протоколу, живёт со стороны протокола. При будущем выносе кодека NRDocument остаётся в nrd-core.
- **resolve** — движок. `${}` — язык подстановки движка (§7 format-spec), не часть mdd.
- **json5-value** — формат. Рантайм-деп `@kerneldreams/nrd/chat` (parseJson5) остаётся как есть (DECISIONS 16.07); при будущем выносе кодека сработает вендор-синк-триггер.

## 3. Обратные рёбра — устранить

Инвариант: ни один модуль format/ не импортирует модули движка. Сегодня нарушают два ребра, оба type-only:

### 3.1 types → icontext (`Value`)

`Value` переезжает в `format/types.ts` как базовый тип. `icontext.ts` импортирует его оттуда и реэкспортирует (публичная поверхность `@kerneldreams/nrd` не меняется).

### 3.2 icontext → document (`NRDocument` в CastMap)

Убрать импорт из icontext. CastMap расширяется через module augmentation из `document.ts` (механизм уже задекларирован в CastMap). icontext перестаёт знать о document.

## 4. Entry `./format`

package.json exports дополняется:

```
"./format": { "types": "./dist/format/index.d.ts", "import": "./dist/format/index.js" }
```

`format/index.ts` экспортирует всю поверхность кодека: parseDocument (парс без движковых обвязок — уточнить фактическую сигнатуру при реализации: если parseDocument сегодня возвращает NRDocument-обёртку, format-entry отдаёт сырой Document/AST + parse-утилиты, а обёртка остаётся в корневом entry), serialize*, schema-слой (parseWithSchema/serializeWithSchema), typed-header, tbl, coerce, placeholder-сканер, json5-value, includes, типы.

Корневой entry `.` продолжает экспортировать всё (формат + движок) — совместимость 100%.

## 5. Энфорсмент границы

Тест в сюите (не eslint — меньше обвязки): walk по `src/format/**`, парс import-строк, ассерт «нет импортов за пределы format/ и node_modules-белого списка (`@kerneldreams/nrd/chat`)». Красный тест = граница пробита.

## 6. Приёмка

- tsc чист; вся существующая сюита nrd-core зелёная без правок тестов (импорты в тестах чинить можно, семантику — нет);
- новый boundary-тест зелёный;
- смоук: nr-cards собирается и его тесты зелёные при импорте ТОЛЬКО из `@kerneldreams/nrd/format` (правка импортов nr-cards — в объёме таски);
- потребители движка (nrd-context, nrd-exec, ntpl) — tsc чист без правок;
- публикация: npm run build → nr libs publish --changed (nrd-core, nr-cards).

## 7. Вне объёма

- Вынос кодека в отдельный пакет (ждёт триггера).
- Баги коэрции/гвардов —, не смешивать.
- Любые изменения грамматики/семантики формата.
