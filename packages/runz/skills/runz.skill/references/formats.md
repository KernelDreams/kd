# formats — синтаксис mdz / mdd / mds

Как выглядит и что значит. Норматив — канон-спеки внизу; при расхождении прав канон.

**Одна идея на весь файл:** mdz `$` = **исполнение** (лента конфига, повтор ключа
переприсваивает — побеждает НИЖНИЙ, `.mdz`), mdd `@` = **данные** (снимок,
`.md`/`.mdd`). Грамматика идентична, различие — только сигил. Разносигильность и
есть механизм вложения: mdz живёт гостем внутри mdd или чужого текста, не
конфликтуя за служебные символы.

`.mds` — тот же язык лентой: звено объявляет тип атрибутом (`$nr-type`), а не именем
блока. Тот же кодек; запуск — `runz <file.mds>` (см. `runz.md`).

Дальше примеры на `$`, для mdd подставь `@`.

Ведущий UTF-8 BOM снимается кодеком (`parse`, включённые файлы, `readTextSync` /
`loadProgram` в `nrd/node`; nr-md ≥ 0.2.1, nrd ≥ 1.5). Раньше он прилипал к первой
строке и молча съедал первый атрибут (`$type` не работал).

## Блок-заголовок

`## $name` — блок типа name; `## $name id` — с адресом-id (для инструментов, не
свойство данных); `## $@` (короткая форма `## $`) — закрытие блока, возврат в
global-зону.

`#`×N задаёт уровень (h1–h6) = вложенность. Имя `[A-Za-z_][A-Za-z0-9_.-]*`, точка
литеральна (`## $example.org` валиден). Несколько блоков одного имени = коллекция.
`## $$` НЕ валиден. Документы начинаются с `##`, `#` — неявный корень.

**Дублирующиеся блоки не удалять:** два блока с одним id — легальная лента, при
чтении по имени побеждает ПОСЛЕДНИЙ, но `cast('records')` отдаёт оба.

## Атрибут (`$key: value`)

Ключ `[A-Za-z_][A-Za-z0-9_.-]*`, значение до конца строки (коэрсится, ниже).
Принадлежит ближайшему предшествующему блоку (или корню). **Точка в ключе
литеральна:** `$a.b: 1` — ОДИН ключ `a.b`, не путь `a→b` (прогон: `get(['a.b'])` → `1`,
`get(['a','b'])` → `undefined`). Иерархия — блоками или телом: так требует каскад.

Namespace `nr-*` зарезервирован (`$nr-type`, `$nr-parse`, `$nr-extends`, `$nr-raw`, …) —
системные директивы, не данные. Три записи декларации эквивалентны: `$nr-type: file`
≡ `$nr.type: file` ≡ `$nr: {type: 'file'}`, плоская побеждает при конфликте. Свои
ключи с `nr-` не начинай.

## Тело и коэрсия значений

Всё, что не заголовок и не атрибут — сырая строка тела. Движок её не интерпретирует:
смысл придаёт `cast` (`text`/`lines`/`prompts`/`paragraphs`/`records`/`messages` —
см. `nrd.md`): одно тело — N интерпретаций.

Значения атрибутов коэрсятся без схемы, YAML-подобно: `true`/`false` → boolean ·
`42`, `-7`, `3.14` → number · `"..."` → string (кавычки сняты, коэрсия НЕ идёт) ·
`null` → null · пусто → `""` · прочее → string. Прогнанные ловушки: `"42"` → строка;
`1.10` → `1.1` (нужна строка — бери кавычки); `+42` и `007` → строки (ведущий `+` не
знак; ведущий ноль + >1 цифры = id/код); `man, sitting, chair` → ОДНА строка.

Кавычки сильны только в позиции скаляр-литерала (значение атрибута, элемент flow,
аргумент функции); в тексте кавычка — обычный символ: `$json: {"m": "${x}"}` → `${x}`
РЕЗОЛВИТСЯ.

## JSON5-объект как значение атрибута

`$cfg: {model: 'gpt', retries: 2}` — однострочный JSON5-объект, `get(['cfg'])` →
JS-объект (прогнано). Детекция строгая, по форме: значение начинается `{` **и**
кончается `}` → обязано быть валидным JSON5, битое → `Json5ParseError` с ключом и
строкой (`$bad: {a: }` → «$bad (line 1): JSON5: invalid character…»), а не тихая
строка. `{name} says hi` (нет `}` в конце) — обычная строка.

- Строка в фигурных — эскейп начала: `$lit: \{not json}` → строка `{not json}`;
  кавычки тоже форсируют строку (`$q: "{a: 1}"`). Сериализатор эмитит `\{`.
- Шаблонизированный объект легален: `$json: {model: '${model}', retries: 2}` после
  резолва (`resolveBlockValue`) — объект. Право на тип даёт сырая форма: `$n: ${x}`
  остаётся строкой, даже если `x` = `"{a: 1}"`.
- Объект атомарен: при last-wins заменяется целиком, deep-merge нет. Внутрь пути нет:
  `get(['cfg','model'])` → `undefined`; `${cfg}` в тексте → канонический JSON5-текст
  (`{model: 'gpt'}`), не объект. Нужна гранулярность — блоки.
- Только объект: массив — flow `$[…]`; во flow-элементах и tbl-ячейках детекции нет.

## Flow-литералы и tbl

`$key: $[a, b, c]` → `["a","b","c"]` (сигил + `[`; каждый элемент коэрсится),
`$[1, 2, true]` → `[1, 2, true]`, `$[]` → пустой список. Голая запятая — не список;
только скаляры без вложенности. **Сигил flow равен сигилу документа:** в mdd это
`@[a, b]`, а `$[a, b]` там остаётся строкой (прогнано).

**Вложенный список во flow — ошибка разбора** (nr-md ≥ 0.2.1): `$k: $[[1,2], x]` →
`FlowParseError` с `line`/`column`/`key` («nested list in a flow literal is not
supported»), а не прежний мусор `['[1', '2]', 'x']`. Критерий — запятая внутри
открытой неэкранированной `[` вне кавычек. Скобочная группа без запятой — текст
скаляра, как раньше (`@[[OOC], abb]` → `['[OOC]', 'abb']`; `$k: $[[file]]` без
резолва инклуда → `['[file]']`). Скобки в кавычках (`$["[1,2]", x]`) и
экранированные (`\[`) — текст. Вложенность пишется JSON5-объектом или блоками.
Сериализатор кладёт элементы со скобками в кавычки.

Таблицы (tbl) — в теле блока, когда элемент = структура: разделитель `|`, первая
строка — заголовок (`weight:number | tags:list(;) | rare:boolean!` — типизированный,
`!` = required), `//` — комментарий.

## Инклуды и эскейпы

`$[[path]]` / `@[[path]]` — включение файла на месте, `$[[path#Section]]` — секции
(заголовок без учёта регистра, до следующего того же/старшего уровня),
`$[[#Section]]` — секция текущего текста. Парсер распознаёт, но не читает:
подстановку делает рантайм — на Node `readTextWithIncludes` из `nrd/node` (на ней
`buildRuntimeContext` и `loadProgram`, руками не зови). Там путь **вложенного**
инклюда резолвится от папки файла, где он написан (не от корневого документа);
без расширения — как есть, затем `.mdz` → `.md` → `.mdd` → `.mds`
(`INCLUDE_EXTENSIONS`); не найден → остаётся как есть + warn в stderr; цикл — throws
`IncludeCycleError` с `chain` (id от повторившегося до него же; прогнано на
`a → b → a`). Класс экспортируют `nrd/format` и `nrd/node` (nrd ≥ 1.2.1) — ловить
`instanceof`, это один и тот же класс.

Свой загрузчик (не fs) — `resolveIncludes(text, readFile, opts)` /
`resolveIncludesAsync` из корня nrd (nr-md ≥ 0.2.0). `IncludeOptions`: `sigil`,
`maxDepth` (10), `from` (id корня), `resolvePath(target, from)` → id или `undefined`
(= не найден), `onCycle: 'keep'|'throw'`. Без `resolvePath` — старое поведение:
цель уходит в `readFile` дословно (вложенные — как их поймёт `readFile`), цикл
молча остаётся текстом (`keep` — дефолт). Эскейпы: `\$` `\@` сигил · `\[`
скобка · `\${` литеральный `${` (opt-out резолва, прогнан) · `\\` `\n` `\t` ·
`\.` точка в пути внутри `${}` · `\,` запятая внутри flow · `\{` в начале значения атрибута — строка, не JSON5-объект. Других нет.

## `${}` кратко (полностью — `nrd.md`)

`${...}` резолвится об ЦЕПОЧКУ читателя, не об документ. Формы: `${a.b.0}` (путь),
`${fn(a, b)}` (вызов), `${a.${b}}` (вложенность), `\${x}` (opt-out — литерал).
Opt-out держится сквозь рекурсию (nrd ≥ 1.5, nr-contracts ≥ 1.3): в контексте
значение лежит **сырым** — `$u: a \${b} c` и `$u: "a \\${b} c"` одинаково дают
`ctx.get(['u'])` = `a \${b} c`; сворачивают эскейп только выходы — `resolve`/
`resolveValue` (`${u}` → `a ${b} c`, `b` не подставлен), `get(path, ctx)`,
`helpers.attr`/`list`. Литерал из контекста читай ими, не `asText(ctx.get(...))`.
Голый `${x}` — свободная переменная (её даёт читатель), `${self.x}` — связанная
(автор-стабильная). `{{...}}` — не `${}`, а макросы шаблонизатора; не смешивать.

## Документ ⇄ JSON — `toJson` / `fromJson`

Состояние документа одной машинной строкой — туда, где текст формата неуместен
(state бота внутри гритинга, поле БД). Обычный JSON, не JSON5. Корень `nrd` и
`nrd/format`, nrd ≥ 1.2:

```ts
const doc = parseDocument(text, { sigil: '$' })
const line = JSON.stringify(toJson(doc))       // {"v":1,"sigil":"$","root":{…}}
serialize(fromJson(line))                      // тот же текст (прогнано)
```

- **`toJson` берёт `NRDocument` или `Document`** (`parseDocument(…)` / `parse(text)`;
  у `NRDocument` берётся `.doc`), nrd ≥ 1.5.1. Прочее — `TypeError: toJson: expected
  Document or NRDocument, got <тип>`. До 1.5.1 — только `Document` (`toJson(doc.doc)`),
  `NRDocument` ронял невнятным `Cannot read properties of undefined`.
- Форма: `{v, sigil, root}`, блок — `{name, id?, level, attrs?, body?, children?}`,
  атрибут — `[key[], value]`; JSON5-объект — `{$o: …}`, значение с `${}` —
  `{$i: raw, p: [[start, end]]}` (плейсхолдер не резолвится, едет сырым).
- `JSON_FORM_VERSION` (= 1) растёт только при несовместимой смене; неизвестные поля
  `fromJson` игнорирует. Нарушение формы, NaN/Infinity — `TypeError`.
- `fromJson` принимает объект или строку.

## Точечная правка текста — `setAttr` / `removeAttr` / `ensureBlock`

`parse → serialize` переписывает документ в канон: `$//`-комментарии переезжают,
пустые строки и `## $@` пропадают. UI, который пишет в `.mdz` (форма, граф), правит
текст точечно — меняется одна строка атрибута, остальное байт в байт. nr-md ≥ 0.3.0;
**до публикации 0.3.0 — только прямым импортом из `@kerneldreams/nrd/md` по
`file:`-ссылке, в `nrd/format` появится после.** Спека — `specs/nr-md-edit-spec.md`.

```ts
import { setAttr, removeAttr, ensureBlock, EditTargetError } from '@kerneldreams/nrd/md'
let t = ensureBlock(src, [{ name: 'step', id: 'save' }])         // нет — допишет в конец
t = setAttr(t, [{ name: 'step', id: 'save' }], 'dst', 'out.txt')  // замена или вставка строки
t = removeAttr(t, [], 'draft')                                    // все строки ключа в корне
```

- Путь `BlockPath = {name, id?}[]` от корня; каждый селектор — первый ребёнок с этим
  `name` (и `id`, если задан); пусто/`undefined` — корневая зона. Нет блока →
  `EditTargetError` с путём. `setAttr`/`removeAttr` блоков не создают. Ключ —
  одно имя, точка — часть имени. `opts`: `sigil`, `baseLevel`.
- `setAttr`: правит **последнюю** строку ключа, всё до значения сохраняет; нет ключа —
  новая строка после последнего атрибута блока / после заголовка / первой строкой
  документа (корень без атрибутов). Значение — `serializeValue`, обязано влезть в
  строку (иначе `Error`). То же значение → та же строка `text`.
- `removeAttr`: удаляет **все** строки ключа (иначе всплыл бы верхний дубль).
- `ensureBlock`: один селектор верхнего уровня; нет — пустая строка + заголовок в конец,
  решёток как у первого блока верхнего уровня (нет блоков — две).
- Перевод строки вставок — стиль документа, BOM сохраняется. Функции чистые.
- Правка видит документ глазами парсера: `$key: v` внутри ``` в теле — тоже атрибут
  блока, его и правит (заборов кода грамматика не знает).
- `parse(text, { positions: true })` заполняет `pos` (`{line, col: 1, offset}` начала
  строки) у атрибутов и заголовков блоков; по умолчанию выключено.

Строишь документ с нуля → `serialize`; меняешь документ, который пишет и человек → эти три.

## Сообщения — `%role` и типизированные фенсы

Отдельный слой в теле; читается как `doc.cast('messages')` или `doc.split()`. `%role`
(`user`/`assistant`/`system`/…) — конверт сообщения, текст между конвертами — неявные
text-блоки. Типизированный фенс — **ЧЕТЫРЕ** бэктика + `%type` (`thinking`,
`tool_use`, …), закрывается такой же строкой, тело opaque. Три бэктика — обычный
markdown и граница исполняемого тела в exec-блоках (см. `nrd.md`).
