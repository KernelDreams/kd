# examples/notebook — блокнот запросов

`site-chat.mds` — один файл, который одновременно тулза, конфиг и журнал.

```
runz rz examples/notebook/site-chat.mds
runz rz examples/notebook/site-chat.mds --request=<url персонажа>
```

## Как устроено

- `%fn go` — хендлер прямо в файле, ничего больше не нужно;
- `%source cfg` — токен из `site.config.md` декларацией, не в коде;
- работа = последний `%request` без `%result` после него. Отсюда
  идемпотентность даром: повторный запуск ничего не делает;
- `--request=` дописывает новый `%request` в конец и обрабатывает его;
- результат дописывается блоком `%result` в этот же файл — история
  остаётся артефактом, а не улетает в stdout.

## Зачем

Баг чуба: «начать чат» создаёт битый чат, который не открыть и не удалить,
а кнопка потом ведёт именно на него. Повторить попытку через UI нельзя.

Установлено прогонами:

- 500 на `POST /core/chats` — **не отказ**: чат создаётся, но битым
  (`tail_id: null`, `chat_count: 0`);
- ошибка **нестабильна** — повтор того же запроса обычно проходит.
  Повтор и есть смысл скрипта (`--retries`, по умолчанию 5);
- признак успеха — `chat_count > 0` (гритинг записан), а не код ответа;
- `DELETE /core/chats/{id}` тоже отдаёт 500 — через API пустышку не убрать;
- `character_id` в `GET /core/chats` **игнорируется**: возвращаются все чаты,
  фильтровать надо самому по `characters.full_path`. Вероятно поэтому UI и
  «кидает на сломанный» — берёт последний по времени.

## Найденные ограничения rz

1. `%include {file:}` в mds **не реализован** — использован `%source`.
2. Абсолютный путь пришлось писать обратными слэшами (баг `fsStorage`, DEBT).
3. Round-trip `parse → stringify` съедает пустую строку между блоками —
   для самопереписывающегося файла диффы шумнее нужного.
