# examples/botchat — один потребитель, разные источники

Прогонять из `appz/rz`: `runz rz examples/botchat/<file>`

Цель: доказать, что шаблон и цикл не знают, откуда пришли данные.
Меняется только объявление источника и маппинг полей.

Фикстуры лежат рядом (`card.json`, `bot.md`) — одни и те же тексты в двух
формах. Живая карточка подставляется без правки файла:
`runz rz examples/botchat/from-mdd.mdz --card_path=<path>` (CLI сильнее
атрибута документа).

Зонды — тесты: `test/botchat.test.ts` (приёмка text-cast-spec §4).

## from-json.mdz — плоский источник

Экспорт с чуба: глубокая адресация в чужую структуру,
`${card.node.definition.personality}`.

```
  поле        длина  начало
  name         11  Carly & Rob
  persona     604  # Carly (26) Прототип: тёплая, торопливая…
  scenario    521  ## NPC # Rob (28) Муж Карли, друг игрока…
  greeting    397  Жара стоит стеной с самого утра…
  system        0
```

## from-mdd.mdz — источник с телами блоков

Тот же файл, изменены только `parse: mdd` и пути полей. Исходник бота
хранит контент в **телах блоков** (`## @personality` + проза), а имя —
в заголовке (`## @name Carly & Rob`). Вывод совпадает с шагом 1 до символа.

Раньше здесь текли `[object Object]` (тело блока было недостижимо из
`${}` — только через `cast('text')` из кода). Чинит единое правило
приведения к тексту, text-cast-spec §2.1: текстовая проекция звена, а нет
её — json5-дамп. `[object Object]` не появляется никогда.

## text-cast.mdz — граница «дерево ↔ текст»

Что происходит со значением в разных позициях (§2.1–§2.3):

```
  whole — дерево  : true                       позиция целого значения
  whole — текст   : # Carly (26) П              String() того же значения
  адресация внутрь: ru                          ${card.meta.lang}
  в строке        : персона — # Carly (26) Про  интерполяция
  дамп через ${}  : дамп — {name: ['Carly & Rob'], lang: 'ru'}
  дамп через код  : дамп — {name: ['Carly & Rob'], lang: 'ru'}
  дамп совпал     : true                        §2.2: String() = интерполяция
  пустое поле     : []                          пустое звено — пустота, не {}
```

Дерево остаётся деревом: `$x: ${card.personality}` — контекст,
адресация внутрь работает. Правило текста включается только на границе
«значение → текст».

## Нерезолвленный плейсхолдер

Ключа нет → в lenient (дефолт) `${card.system}` остаётся литералом и
уехал бы в промпт как есть. Для деклараций это чинится опцией хоста:
`buildContext(cfg, { mode: 'strict' })` роняет сборку с именем ключа и звена
(nrd-context, text-cast-spec §2.4). Дефолт не меняли — comfy-батчи опираются
на lenient.

## Побочно найдено

Абсолютный Windows-путь с прямыми слэшами не распознаётся как абсолютный и
приклеивается к baseDir; с обратными тот же файл читается. Unix-центричная
проверка абсолютности в `fsStorage` (nr-infra) — тот же класс, что чинили в
`resolveFSPath` (§1.5). В DEBT, не в этой таске.
